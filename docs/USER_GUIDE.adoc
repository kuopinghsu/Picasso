Picasso is a free, open-source photo library, viewer and editor for Windows, macOS and Linux.
It organizes photos in your existing folders and lets you edit them without changing the original files.
No cloud account is required, and photos and videos are not uploaded.

This guide covers installation, everyday tasks, editing, maps, trips and stories, and library recovery.
For a first session, follow <<install>> and <<first-start>>, then try <<editing>> and <<exporting>>.
To build Picasso from source, see the https://github.com/kuopinghsu/picasso/blob/main/README.md[README].

NOTE: Shortcuts are written with kbd:[Ctrl].
On a Mac, use kbd:[⌘] instead, so kbd:[Ctrl+A] is kbd:[⌘+A].

[#install]
== Installing Picasso

Download Picasso from the https://github.com/kuopinghsu/picasso/releases/latest[latest release].
Use `x64` packages on Intel and AMD processors, and `arm64` ones on 64-bit Arm processors.

Windows::
Supports Windows 10 and 11 on x64 and Arm64.
Download the `.exe` and run it. No installer is required.
The `.zip` holds the same program with the READMEs and the license.

macOS::
Supports macOS 11 or later on Apple silicon and Intel Macs; use the universal package.
Open the `.dmg` and drag Picasso to *Applications*.
Unless the release notes say the app is notarized, the first launch is blocked.
Click *Open Anyway* in *System Settings → Privacy & Security*, then confirm.
On macOS 14 and older, Control-clicking Picasso and choosing *Open* also works.

Linux::
The `.AppImage` is available for x64 and Arm64 and runs without installation on Ubuntu 20.04, RHEL 8, Debian 10 and newer.
Replace the version and processor name in this example with those of your download:
+
[source,bash]
----
chmod +x picasso-<version>-linux-x64.AppImage
./picasso-<version>-linux-x64.AppImage
----
+
For Ubuntu 22.04 or newer, `sudo apt install ./picasso-<version>-linux-x64.deb` installs Picasso with its menu entry.
Use the Arm64 filename on an Arm system.
If FUSE is unavailable, start the AppImage with `--appimage-extract-and-run`.
The `.tar.gz` contains the executable, desktop entry and icon for manual installation; it is built on Ubuntu 22.04.
File dialogs use the XDG desktop portal, normally provided by the desktop environment.

Release downloads include PDF guides in English and Traditional Chinese.
To verify a download, compare its SHA-256 checksum with the entry in `SHA256SUMS.txt`.

[#ffmpeg]
=== Optional video support

Picasso plays videos with https://ffmpeg.org[FFmpeg].
Without it, photos work and videos are skipped; they are added once FFmpeg is installed.

* Windows: `winget install Gyan.FFmpeg`
* macOS: `brew install ffmpeg`
* Linux: `sudo apt install ffmpeg`, or your distribution's package

Both `ffmpeg` and `ffprobe` must be available.
Picasso searches `PATH`, common WinGet and Homebrew locations, and the application folder.
For a portable setup, place both executables beside Picasso or the AppImage, or in an `ffmpeg` subfolder.
You can also set `PICASSO_FFMPEG` to their folder or the FFmpeg executable.

[#first-start]
== Getting started

On first launch, Picasso adds your Pictures folder if it exists and scans it in the background.
The status bar shows scan progress. Photos appear by date as they are found.
You can use Picasso while it scans.

To add another folder, click *+ Import* at the top right, or drag the folder onto the window.
Picasso adds every subfolder too.

Importing a folder indexes its files in place; it does not copy or move them.
Stars, captions, albums, assigned locations, date corrections and edits are stored in the library.
GPS track matching also creates sidecar files beside the photos.
Explicit file operations, such as *Rename files…* and *Move to trash*, affect files on disk.

. Select a photo and press kbd:[Enter] to view it.
. Press kbd:[E] to edit it, or kbd:[S] to add a star.
. Choose *Export…* to save an edited copy for use outside Picasso.
. Press kbd:[F1] for help with the current tools.

=== Supported files

Picasso supports JPEG, PNG, GIF, WebP, BMP, TIFF, HEIC/HEIF and camera RAW files.
For some cameras not supported by the RAW decoder, it uses the embedded JPEG preview.
Video formats include MP4, MOV, AVI, MKV and WebM; videos require FFmpeg and cannot be edited.
Choose which categories to scan in *Settings → File types*.

== The library window

The window has four parts:

The sidebar::
*Library* shows every photo.
Below it are *Starred Photos*, *Places*, *Statistics*, *Travel Map*, and *Duplicates*, then your albums and the folder tree.
Each folder shows how many photos it holds.

The top bar and the toolbar::
The top bar holds the search field.
Above the grid are the title and photo count, the sort order, and buttons that act on the selected photos.

The grid::
Thumbnails grouped by the day they were taken.
When the photos are sorted by date, a strip beside the grid lists the years, with the months of the year in view; click one to jump there.
Dragging the scroll bar shows the date in view.

The status bar::
Scanning progress, the *Photo Tray* with the selected photos, and a link to files that couldn't be read, when there are any.

At the top right are *+ Import*, *Refresh*, *Slideshow*, *?* for *Help & Shortcuts*, and the gear for *Settings*.
Click the logo at the top left to open *About Picasso*, which shows the version, build date and source commit.

Press kbd:[I], or click the side panel button at the right of the bottom bar, to show or hide the Info and Map panel beside the grid.
It shows the selected photo's camera details and where it was taken, on the *Info* and *Map* tabs at its top.
In Places the same button shows or hides the list of what is on the map.
The slider beside the button sets the thumbnail size; it shows only where there are thumbnails, so not in Places, Statistics, or the Travel Map, which also have no side panel button.

== Finding photos

=== Sorting

The sort menu in the toolbar offers:

* *Sort by Date*, newest first, or *Sort by Date, oldest*
* *Sort by Name*

Use the separate *Edited only* checkbox to show photos with edits.
It works with any sort order. Clear the checkbox to show all photos in the current view.
When a search has no results, use *Clear search*; an empty edited view offers *Show all photos*.

=== Searching

Type in *Search photos* at the top of the window to find photos that match every word you type.
Picasso looks in the file name, the folder path, the caption, the camera, the lens, and album names.

A date finds the photos taken then:
`2019` finds that year, `2019-05` that month, and `2019-05-17` that day.
You can also write `2019/05` or `2019.05`.
Dates and words combine, so `2019-05 beach` finds the May 2019 photos that match "beach".

Search words narrow the results further:

* `type:video`, `type:photo`, or `type:raw`, or one format such as `type:jpg` or `type:nef`
* `gps:yes` or `gps:no`, for photos with or without a place on the map
* `is:edited` or `is:starred`
* `is:notrip` or `is:intrip`, for photos in no Trip or in one, and `is:review` for Trip photos whose time needs review
* `trip:`, `day:`, `place:`, or `story:` with part of a Trip's title or destination, a Day's title, a Place's name or local name, or a Story's title, such as `place:alfama`
* `camera:` or `lens:` with part of the name, such as `lens:50mm`
* `focal:35`, or a range such as `focal:24-70` or `focal:200-`, in millimeters
* `mp:12`, or a range such as `mp:20-` or `mp:-8`, in megapixels
* a word starting with `-` leaves out the photos it would find, so `beach -type:video` finds the beach photos but not the videos

kbd:[Ctrl+F] jumps to the search box from anywhere but the editor, closing the viewer if it is open.

When you click in the search box, it lists your ten most recent searches, and once you type, only those that contain what you have typed.
Click one to search for it again, or pick one with kbd:[↑] and kbd:[↓] and press kbd:[Enter].
A search is added to the list when you press kbd:[Enter] or click away from the box.
The list is kept in `settings.json`, so it is there the next time you start Picasso; *Clear recent searches* at the bottom of the list empties it.

=== Selecting

* Click a photo to select it.
* kbd:[Ctrl]-click adds a photo to the selection or takes it out.
* kbd:[Shift]-click selects every photo between the last one you clicked and this one.
* kbd:[Ctrl+A] selects every photo in the grid.
* The arrow keys move the selection.
* The ★ button in the toolbar selects the starred photos in view.

The selected photos appear in the *Photo Tray* in the status bar.
*Clear* empties it.

== Organizing photos

Most actions are in three places: the toolbar above the grid, the *Photo Tray*, and the menu you get by right-clicking a thumbnail.
Selection actions apply to all selected photos. Caption editing applies to the open photo.

=== Stars

Press kbd:[S], or click the star in the toolbar, to add or remove stars from the selected photos.
The thumbnail right-click menu also applies Star or Unstar to the selected photos and shows their count.
*Starred Photos* in the sidebar lists them all.

=== Captions

Open a photo, press kbd:[I] for the details panel, and type in the *Caption* field.
Search finds photos by their captions.

=== Albums

Albums group photos from any folders without moving the files.

* To make an album, select photos and choose *New album…* from *Add to Album* in the toolbar.
* To add photos to an album, select them and pick the album from *Add to Album*.
* In an album, *Remove from Album* takes the selected photos out.
The files remain unchanged.
* To delete an album, right-click it in the sidebar and choose *Delete album*.
The photos stay in the library.

=== Rotating

Press kbd:[R] to turn the selected photos clockwise, or kbd:[Shift+R] to turn them counterclockwise.
The rotation is kept in the library; the file is not rewritten.

=== Fixing the date taken

To correct a camera clock error or set the date of scanned photos, select the photos, right-click one and choose *Adjust date…*.

* *Shift* moves every selected photo by a number of days, hours, and minutes.
* *Set to* sets the earliest photo to a date and time, and moves the others with it.
* *Use the date in the file* undoes your changes.

The corrected date is stored in the library and remains after rescanning. The files are unchanged.

=== Moving photos to the trash

Press kbd:[Delete], or click *Delete* in the *Photo Tray*, to move the selected photos to the system trash.
Picasso asks first unless you turned that off in *Settings → General*.

On Windows and Linux, the status bar offers *Undo* for two minutes, which puts the files back where they were.
On macOS, restore files from the Trash in Finder.
Either way, a photo that comes back within 90 days gets its stars, caption, albums, and edits back.

=== Renaming files

Right-click a folder in the folder tree and choose *Rename files…* to rename its photos and videos from a pattern, as `+exiftool "-filename<${DateTimeOriginal}%-03c.%le" -d %Y.%m.%d-%Hh%Mm%Ss .+` does.
Only the files directly in that folder are renamed, not those in its subfolders.

Type the pattern in *New name*, or click the keywords under it to add them:

* `+${DateTimeOriginal}+` is the date taken and `+${FileModifyDate}+` the date the file last changed, both written in the *Date format*
* `+${Model}+` is the camera, as the Info panel names it
* `%f` is the old name without its extension
* `%-03c` is a copy number added only when the name is taken, so photos taken in the same second get `-001`, `-002`, and so on
* `%le` is the extension in lowercase, and `%e` the extension as it is

In the date format, `%Y` is the year, `%m` the month, `%d` the day, `%H` the hour, `%M` the minute, and `%S` the second, so `%Y.%m.%d-%Hh%Mm%Ss` gives `2023.05.17-14h30m05s`.
The date taken is the one Picasso shows, including a date you fixed, with a video's time in local time, as exiftool's `-api QuickTimeUTC=1` gives.
For a file with no date in it, that is the date the file last changed; use *Adjust date…* first to give it another.

*Time offset* moves the dates in the names for a camera whose clock was off, as exiftool's `-globalTimeShift` does: `+1:30` is an hour and a half later, `-0:00:10` ten seconds earlier, and `+2 0:00` two days later.
It changes only the names and isn't kept for next time; to fix the dates Picasso shows as well, use *Adjust date…* instead.

The list shows every file's new name before anything changes.
A name that can't be used, such as one without the file's extension or with a `:`, is shown in red, and that file keeps its name.
A file already named by the pattern keeps its name, so renaming twice changes nothing.
*Rename* renames all the files or, if one can't be renamed, none of them; the photos keep their stars, captions, albums, edits, and places.
The `.xmp`, `.aae`, and `.thm` files that go with a photo are renamed with it, so `DSC0001.xmp` and `DSC0001.JPG.xmp` follow `DSC0001.JPG`.

Each renaming is listed in a `.picasso-renames.json` file in the folder, with every old and new name.
*Undo* puts back the names from before the newest renaming in the list, also after Picasso was closed, and clicking it again goes back one more.
A file whose earlier name another file has now, such as a new `DSC0001.JPG` from the camera, keeps its name and stays in the list for later.

[#duplicates]
== Finding duplicates

*Duplicates* in the sidebar finds files whose content is identical, byte for byte, even under other names or in other folders.
The search runs in the background and continues when you close the Duplicates dialog, while Picasso remains open.
The sidebar shows the number of groups found.
It finds exact copies, not photos that only look similar.

In each group one file is *Kept*: a starred or edited one when there is one.
Move the other copies to the trash one by one, with *Trash extra copies* for a group, or with *Move all extra copies to trash*.
*Search again* looks once more.

== Unreadable files

When a scan finds files it can't read, such as a damaged photo, a link appears in the status bar.
It opens the list, with *Show in folder* and *Move to trash* for each file.

== Viewing photos and videos

Double-click a photo, or select it and press kbd:[Enter], to open the viewer.

* kbd:[←] and kbd:[→] go to the previous and next photo; kbd:[Home] and kbd:[End] go to the first and last.
* Zoom with the mouse wheel, kbd:[Ctrl] and the wheel, a trackpad pinch, or kbd:[+] and kbd:[−].
Drag to pan.
* kbd:[0] fits the photo to the window, and kbd:[1] shows it at actual size, with one image pixel per display pixel.
* The filmstrip along the bottom shows the photos around this one; click one to go there.
* kbd:[I] shows the details panel with the camera settings, a histogram, the *Caption*, *Show in folder*, and *Show on map*.
* kbd:[F11] switches to full screen, and kbd:[Esc] goes back to the library.

Use the theme button in the viewer toolbar to switch between light and dark themes.

=== Slideshows

Click *Slideshow*, or press kbd:[Space] in the viewer, to play the photos from the selected one.
kbd:[Space] pauses and resumes, and kbd:[Esc] ends the slideshow.
*Settings → General* sets how long each photo shows.
Each photo fades into the next.
*Shuffle* in the toolbar, or kbd:[Shift+S], plays the photos in a random order, each once before any comes again.

=== Copying and opening photos elsewhere

* kbd:[Ctrl+C], or *Copy picture*, puts the photo on the clipboard with its edits, at up to 4096 px, to paste into another app.
* *Copy path* copies the full path of each selected photo, one per line.
* *Open with default app* opens the file in the app your system uses for it.

They are on a thumbnail's right-click menu and the viewer's *···* menu.

=== Videos

Videos show in the grid with a play badge and their length.
In the viewer, kbd:[Space] plays and pauses, and kbd:[M] mutes.
Videos cannot be edited.

[#editing]
== Editing photos

Open a photo and press kbd:[E], or click *Edit*, to open the editor in place of the details panel.
Editing never changes the file.
Each change is saved as a step in the library. Picasso renders the photo from the original file and the saved edits.
An edited photo has a small sliders badge on its thumbnail; click it to edit the photo again.

image::editor.png[The editor]

At the top of the editor are four tools, *Adjust*, *Crop*, *Transform*, and *Masks*.
Below them are undo and redo, a ··· menu with *Undo all*, *Redo all*, *Reset all*, *Copy*, and *Paste*, a live histogram, and the *Before*, *Side by side*, and *Split* buttons with the clipping button.

=== Adjust

*Adjust* holds the sliders, in sections:

[cols="1,3"]
|===
| Section | What it does

| Profile | A base appearance before other adjustments: Color, Neutral, Vivid, Landscape, Portrait, or Monochrome
| Presets | 25 built-in looks with an *Amount* slider; save your own settings as a preset to reuse them
| Transform | Turn, tilt, rotate by 90°, and flip without leaving *Adjust*
| Light | Exposure, contrast, highlights, shadows, whites, and blacks
| Tone curve | A curve with four zones, and point curves for RGB, red, green, and blue
| HDR | Adjusts shadow and highlight detail in a single photo
| Color | White balance, with an eyedropper to sample a neutral area; vibrance and saturation
| Color mixer | Hue, saturation, and luminance for eight colors
| Color grading | Color wheels for shadows, midtones, highlights, and the whole photo
| Effects | Texture, clarity, dehaze, vignette, and grain
| Detail | Sharpening and noise reduction
| Black & White | Monochrome with an eight-color gray mix
| History | Saved editing steps
|===

Double-click a slider's name to set it back to zero.
For a quick start, *Auto tone* in *Light* balances exposure and contrast, and *Auto* in *Color* sets the white balance.

HDR adjusts a single photo; it does not merge several exposures.
AI masks, healing, panorama stitching and lens profiles are not available.

=== Crop

Press kbd:[C] for *Crop*.
Drag the edges or corners of the frame, or drag inside it to move it.
Pick an aspect ratio, or *Free*; ⇄ swaps portrait and landscape.
The *Straighten* slider turns the photo and keeps the crop inside it.
Press kbd:[Enter], kbd:[Esc], or *Done* when you finish.

=== Transform

Press kbd:[T] for *Transform*, which puts a handle on each corner and on the middle of each side.

* Drag a corner to move just that corner, for example to make a leaning building stand straight.
* Drag the middle of a side to skew or stretch the photo.
* Drag inside the outline to move the photo, or outside it to turn it.

The thin frame shows the part that will be kept.
*Reset corners* puts the corners back.

=== Masks

*Masks* adjusts part of a photo.
Click *+ Linear gradient* for a graduated mask, such as for a sky, or *+ Radial gradient* for a round one.
Drag the mask's handles on the photo, then set its *Feather*, *Invert*, and its own exposure, contrast, color, clarity, and dehaze.
A checkbox shows the mask's area in red.

=== Undo, history, and comparing

* kbd:[Ctrl+Z] undoes a step, and kbd:[Ctrl+Y] or kbd:[Ctrl+Shift+Z] redoes it.
* *History*, at the end of *Adjust*, lists every step; click one to go back to it.
* *Before* (kbd:[\ ]) shows the original, *Side by side* (kbd:[Y]) shows both, and *Split* (kbd:[Shift+Y]) puts a divider between them.
* The clipping button (kbd:[J]) marks blown highlights in red and crushed shadows in blue.
* *Reset all* in the ··· menu starts over from the original, as one more step you can undo.

=== Copying edits to other photos

*Copy* (kbd:[Ctrl+Shift+C]) copies the photo's settings, and *Paste* (kbd:[Ctrl+Shift+V]) applies them to another photo.
In the library, *Paste settings* on the right-click menu applies them to every selected photo.
The crop and the *Transform* settings are not copied, because they belong to one photo.

[#exporting]
== Exporting photos

Edits stay inside Picasso until you export.

* In the editor, *Export…* saves the photo you are editing as a new file, `name-edited.jpg` by default.
* For many photos, select them and click *Export…* in the *Photo Tray*, or right-click one.
Choose a *Folder*, a *Format* (JPEG, PNG, or TIFF), a *Size* (*Full size* or a long edge of 4096, 2048, 1600, or 1080 px), and the JPEG *Quality*.

Batch export keeps the original filename with the new extension and adds a number if the name already exists.
It skips videos. The status bar shows progress with *Stop*, then *Open folder* when complete.
Stopping leaves files that have already been exported in the destination folder.

Editor export opens a save dialog where you choose the filename.
It prevents saving over the original photo; choose a new filename if you also want to keep an earlier export.

== Maps and places

Places and the Map panel download tiles from the selected map provider.
Cached tiles can be reused offline, but areas or zoom levels not in the cache require a connection.
Travel Map is separate and works offline with built-in boundaries.

=== Places

image::places.png[Places]

*Places* in the sidebar shows every photo with a location on a map.
Drag to move the map, and zoom with the wheel or a pinch.
Nearby photos are grouped into a pin that shows their count.
Point at a pin for a card with its photos: click one to open it, or use *Select these photos* or *Zoom in*.
Clicking a pin of several photos zooms in on them, or selects them when they were taken at one spot, and double-clicking a single photo's pin opens it.
*Open in OpenStreetMap* opens the same view in your web browser.

A search leaves only the matching photos on the map and frames them, and *Starred only* in the toolbar leaves only the starred ones. A search typed in the Library stays when you open Places, and stays when you go back to the Library, so you can see where the results were taken and return to them. *Show on map* clears the search and *Starred only*, so the photo you chose is always on the map.

From a photo, *Show on map* opens Places at that photo.

=== Placing photos by hand

For photos without GPS:

. Select the photos in the library.
. Open *Places*; it keeps the selection.
. Click *Geotag*, then click the map where the photos were taken.

*Clear geotag* removes the pin you placed.
A location from the camera's GPS is never changed.

== GPS tracks

Picasso reads the `.gpx` and `.kml` files in your folders, and Polarsteps location exports in `.json` files (such as `locations.json`), and draws them as colored paths under the photo pins.
Hover over a track for its name, start time, distance, and duration, and double-click it to zoom to it.
Click a track to select the photos taken along it: those within 300 m of the path and, for a track with times, taken within 14 hours of them, so a camera clock set to another time zone still matches.
*Select the photos taken along it* on the right-click menu of a track in the side panel does the same.
*Tracks* in the Places toolbar turns the paths off.

A folder's tracks are also listed at the top of the library grid, under *GPS tracks*, each with the shape of its path, its format, and its distance.

The library scanner supports GPX tracks and routes, KML lines and timed tracks, and Polarsteps JSON.
It does not index KMZ archives or area outlines.
The geotagging tool described below separately accepts GPX, KML and KMZ files.

=== Opening and inspecting a track

image::trackedit.png[The track editor]

Click a track in the library grid, or right-click it there or in Places and choose *Edit track*, to open the track editor.
When opening an unprocessed track, Picasso applies automatic cleanup using the track settings.
Cleanup removes implausibly fast points, simplifies the path and combines points recorded during a stay.
It can also fill long gaps with a curve. Segments classified as flights are preserved.

The map fills the window.
The tools float at its top left, buttons for the *Whole track*, *Start*, *End*, and *Highest point* at the top, and the zoom at the top right.
The panel on the right shows the *Statistics*, the *Elevation* profile, the selected *Point*, and the *Cleanup* settings.
A track without heights, such as one from Polarsteps, gets a note in place of the profile; a track with 0 m at every point is also treated as having no elevation data.
Click *Look up heights* to download https://github.com/tilezen/joerd/blob/master/docs/attribution.md[Terrain Tiles on AWS] and calculate elevations locally.
The provider receives tile requests for the track area, rather than the track file or individual points.
This reveals the requested terrain area to the provider.
If some points still get no height, the button stays to try those again, and kbd:[Ctrl+Z] takes the heights off.
Hover over the elevation profile to highlight the corresponding location on the map.
Click or drag along the profile to select a point. Hovering over a map point also highlights it on the profile.

=== Editing track points

* Drag a point to move it, and click the line to add one.
* Right-click a point and choose *Remove point*, or select points and click *Remove* in the bar at the bottom of the map.
* Press kbd:[R] and drag a box round points to select several, or kbd:[Ctrl]-click them; kbd:[V] goes back to moving points.
* kbd:[←] and kbd:[→] step from point to point.
* kbd:[Ctrl+Z] undoes and kbd:[Ctrl+Y] redoes.
* kbd:[1] to kbd:[4] show the whole track, its start, its end, and its highest point.
* *Show original* draws the track as read, before the cleanup.

=== Cleanup settings

Steps longer than the *Flight distance* or faster than the *Flight speed* are drawn as a dashed flight, and places where you stayed longer than the *Stay* time get a circle.
Change the settings and click *Clean up again* to clean the track up once more; *Defaults* restores GPXViewer's values.
Settings you change become the defaults for the next track.

=== Saving and recovering track edits

The editor saves copies and prevents overwriting the source track.
*Save as GPX…* and *Save as KML…* save a copy beside the track, named `-optimized` by default, and kbd:[Ctrl+S] saves it in the track's own format.
The copy keeps the cleanup settings and how long each stay lasted, so it opens as saved, without a new cleanup; tracks saved by GPXViewer open as saved too.
Undoing a cleanup also restores the previous cleanup settings.
kbd:[Esc] or *Back* closes the editor, and asks first when there are edits you haven't saved.
Edits you haven't saved are kept a few seconds after each change, so if Picasso quits or stops unexpectedly, it offers to restore them the next time it starts.

[#geotagging]

=== Placing photos from a GPS track

If you carried a GPS logger or a phone app while shooting, Picasso can place your photos by matching their times to the track:

. Right-click the folder in the folder tree and choose *Geotag from GPS track…*.
. Choose the *GPS track* file (`.gpx`, `.kml`, or `.kmz`) and check the *Folder*.
. Set the *Camera time zone*: the offset of the camera's clock from UTC, such as `+01:00`.
Cameras usually keep local time without a time zone.
. Click *Geotag*.

Photos that already have GPS from the camera, or a pin you placed, keep their location.
Picasso writes the places to its library and to a `.picasso-geotags.json` file in the folder, never into the photos.

The track must contain timestamps, and the photo times must overlap the track recording.
If the camera recorded no time zone and you leave the offset blank, Picasso uses this computer’s time zone.
For photos taken elsewhere, enter the offset used by the camera at the time of the trip.

The same works from a terminal, and `--dry-run` shows what would happen without saving anything:

[source,bash]
----
picasso geotag track.gpx ~/Pictures/Trip --offset +01:00 --dry-run
----

Remove `--dry-run` only after reviewing the matches.
Use `picasso geotag --help` for the command options.

Here `picasso` stands for the Picasso program: the `.exe` you downloaded on Windows, `/Applications/Picasso.app/Contents/MacOS/picasso` on a Mac, the `.AppImage` file, or `picasso` once the `.deb` is installed.

== Statistics

image::statistics.png[Statistics]

*Statistics* in the sidebar shows your library in numbers: photos per year and month, the days you took photos, your cameras, lenses, and focal lengths, and how many photos have a location.
Click *All years* or a year to look at one year.
Most items have *Show these photos*, and places have *Show on map*.

== Travel Map

image::travelmap.png[Travel Map]

*Travel Map* colors the countries where your geotagged photos were taken, and the states and provinces of the largest countries.
A deeper color means more photos.

* Switch between *Globe* and *Flat*.
* The side panel counts *Countries visited* and *Continents*, with the *Coverage by continent*.
* Search for a country to find it on the map.
* Click a colored place for a card; *Show photos* shows them in Places.

Travel Map is based on photo locations. It does not provide manual visited-country markers.
It works offline.

[#trips]
== Trips and Stories

A Trip gathers the photos of one journey, sorts them into Days and Places, and keeps the tracks, documents and links that go with it.
A Story turns a Trip into a page to read: text and photos you can preview, export as a web page or Markdown, or publish to your own WordPress site.

Trips never change your photos.
Stars, captions, dates, edits, locations, Albums and files stay as they are, and a photo can be in several Trips.
Everything except publishing works offline.

=== Making a Trip

* Select photos in the library and choose *Add to Trip* to put them in a new or existing Trip.
* *New trip…* on the *Trips* page makes an empty Trip with a title, destination, dates and timezone.
* *Suggest trips…* groups the whole library by when photos were taken, starting a new group after a gap of days with no photos. Pick a group and *Create trip…*. Under *Camera clocks*, shift a camera whose clock was wrong by whole hours; this changes only the grouping, never the photos.

Before photos are added, Picasso shows what will happen: how many photos and videos, their dates, how many are already in this or another Trip, how many have no date, and how many may be copies.
Nothing is written until you confirm.

*All trips* shows each Trip as a card with its cover, dates and counts.
Open one to see its photos; the *Photos* and *Stories* tabs switch between its photos and its Stories, and *Edit trip…* changes its title, dates, timezone and cover.

=== Days and reviewing times

*Suggest days* puts each photo in a Day of the Trip, using the time the camera recorded and the Trip's timezone, and makes a Day for each date that has none.
It reads only the photos' own times and never changes them.
Photos whose time is uncertain, such as those without a recorded time zone or taken around a daylight saving change, go to *Needs review* with the reason.

* Choose a Day to see its photos, or *Not in a day* and *Needs review* to settle the rest.
* Select photos and use *Move to Day*, or press kbd:[Alt+1] to kbd:[Alt+9] for a Day and kbd:[Alt+0] for none.
* *Arrange*, or kbd:[Alt+↑] and kbd:[Alt+↓], changes the order within a Day. kbd:[Ctrl+Z] undoes a move.

Suggesting days again changes only suggestions; Days you assigned, named or reordered stay as you left them.

=== Places

*Suggest places* groups the Trip's photos that have a location into Places: photos taken near each other and close in time are one visit, and coming back to the same spot joins the same Place.
Photos without a location can be placed by a GPS track linked to the Trip; this only groups them and never writes a location to the photo.

Click a Place to see its photos.
*Edit place* gives it a name, a name in the local language and notes.
*Look up name* fills the names from OpenStreetMap; it works only after *Look up place names online* is turned on in *Settings › Map*, and sends only the position rounded to about 100 m.

=== Tracks and resources

*Tracks* links GPS tracks already in the library to the whole Trip or one Day; the track file stays where it is.

*Resources* keeps documents, track files, web links and notes with the Trip: tickets, bookings, maps or anything else for reference.
*Add resource…* records where a file is without copying it; a moved file is marked missing, and *Locate…* finds it again.
Every resource is private.
Tick *May be published* on a link before a Story's *Link* block may use it; files are never uploaded.

=== Finding photos in a Trip

The *Show* row narrows the Trip's photos to the starred ones, those without a location or caption, those no longer in the library, or those used in a Story, together with a Day or Place.

The search box searches the whole library in every view.
These words find Trip photos anywhere:

* `trip:` with part of a Trip's title or destination, such as `trip:spain`
* `day:`, `place:` or `story:` with part of a Day's title, a Place's name or a Story's title
* `is:intrip` or `is:notrip` for photos in a Trip or in none, and `is:review` for photos whose time needs review

[#similar-photos]
=== Similar photos

*Similar photos…*, at the end of the *Show* row, finds photos in the Trip taken close together that look alike, such as a burst or several tries at the same shot.
It is different from <<duplicates>>, which finds exact copies of files.

The first time, Picasso looks at each photo, with a count and *Cancel*; afterwards only new photos are looked at.
Then adjust the groups:

* *Taken within* is the longest time between one photo of a group and the next, 10 seconds unless changed.
* *Alike* runs from near copies on the left to more of a scene on the right.

*Select* on a group selects its photos in the grid, to compare, star or add to a Story.
Nothing is ever deleted, moved or starred for you.
Videos and photos without a date are left out.

=== Writing a Story

*New story* starts a *Blank story*, one made from the selected photos, or one made *From the trip's days* or *From one day*, with a heading for each Day and its photos in order.
The Story opens in place of the Trip's photos and is saved as you type.

* Type in a paragraph; kbd:[Enter] starts a new one. Typing `/` in an empty paragraph lists the blocks, such as `/heading` or `/grid 3x2`.
* Point between blocks and click *+* to add one there, or use the handle to drag a block.
* Select photos in the grid and choose *Add to Story* to add them as single photos, a *Gallery* or a *Photo grid*. Each photo has its own caption and alt text in that Story.
* Blocks include *Heading*, *Subheading*, *Paragraph*, *List*, *Quote*, *Separator*, *Credits*, *Practical info*, *Link* and *Route map*, which draws a linked GPS track on the map.
* *Introduction* and *Conclusion* are optional text before and after the blocks.
* Point at a photo block and choose *Use as cover* in its tools, or right-click the photo. The cover's own tools, on its bottom-right corner when you point at it, have *Frame cover…*, which chooses its shape, a fixed one or *Free* to drag the corners and edges to any shape, and the part of the photo it shows, in this Story only, and *Remove cover*.
* *Add photos…* on a gallery or grid opens a strip of the Trip's photos; *Starred only* and *Not in the story yet* narrow it, and a dot marks photos already used.

Select text and press kbd:[Ctrl+B], kbd:[Ctrl+I] or kbd:[Ctrl+K] for bold, italic or a link.
A Story is a *Draft* until you mark it *Finished*.

=== Templates, preview and export

The Story's template changes how its page looks, never its content: *Photography Journal*, *Travel Diary*, *Travel Guide*, with a *Contents* list, or *Photo Essay*.

*Preview* opens the page in your web browser.
*Export…* writes the Story as a web page or Markdown, with its photos, into a new folder; choose the photo size and JPEG quality.
Exported photos are rendered with your edits and carry no camera details or location.
Before export, Picasso lists anything that needs attention, such as missing photos, missing alt text or low-resolution photos, with a link to each.

=== Publishing to WordPress

Connect a self-hosted WordPress site in *Settings › Publishing* with its address, your user name and an *Application Password* made in WordPress.
The password is kept in the system's credential store, never in the library or its backups.

*Publish to WordPress…*, in a Story's menu, saves the Story as a draft on the site.
Choose the *Photo size* (*Standard web* or *Low resolution*), whether to *Keep camera details*, *Categories and tags*, and *By Day* to make an index post and one post per Day.
The *Summary* lists what will change on the site before anything is sent.
The post becomes public only with *Publish it once saved*, or *At a set time*, after a confirmation of what readers will see.
Locations are never sent, and Picasso never takes a post down; do that in WordPress.

Saving again updates the same draft.
A post edited on the site since is not replaced unless you choose so, and an interrupted job resumes without uploading the same photos twice.
*History* lists the last attempts.

=== Moving, archiving and deleting Trips

*Export trip package…* writes the Trip, its Days, Stories, photos and tracks into one `.picassotrip` file.
*Import trip…* on another computer adds it as a new Trip, reusing photos already in that library.

*Archive trip* puts a finished Trip away with everything in it; *Archived trips* shows it again.
*Delete trip…* first lists what goes with it.
Deleting a Trip or a Story never removes photo files or anything published.
Library backups include Trips and Stories.

== Settings

Click the gear at the top right, or press kbd:[Ctrl+,], to open *Settings*.
Settings apply right away.

General::
Language, color theme, thumbnail size, slideshow interval, and whether to ask before moving photos to the trash.
Automatic *Updates* checks are enabled by default and contact GitHub at most once a day.
Turn them off here, or use *Check now* for a manual check.
When a newer version is found, a download link appears at the top right; Picasso does not install it automatically.

Folders::
The folders Picasso watches, each with buttons to open it, rescan it, or remove it from Picasso.
Removing a folder leaves its files on disk.
*Excluded folders* lists subfolders Picasso skips; *Exclude a folder…* adds one and *Include again* brings it back.

File types::
Which files Picasso adds: JPEG, PNG, GIF, WebP, BMP, TIFF, HEIC/HEIF, camera RAW, and videos.
Files of a type you turn off leave the library but stay on disk.

Map::
Choose the provider used in Places and the Map panel.
*OpenFreeMap Liberty* is the default. It and *OpenStreetMap* require no API key.
*CARTO* has three styles and needs a free key: *Get a free key* opens CARTO's sign-up page, and you paste the key into the field.
*Esri World Imagery* shows satellite photos.

GPS tracks::
The *Track cleanup* settings the track editor uses when it opens a track, with *Defaults* to restore GPXViewer's values.

Storage::
Where the library, the cache, and the settings are kept, how much space each takes, *Clear cache*, and the backups.

=== Folders in the tree

Right-click a folder in the sidebar for:

* *Show in Finder* on a Mac, *Show in Explorer* on Windows, or *Show in folder* on Linux, which opens the folder
* *Geotag from GPS track…*
* *Rename files…*
* *Exclude from scanning*, on a subfolder you don't want in the library
* *Rescan this folder* and *Remove from Picasso…*, on a folder you added

== Library storage and backups

=== What the library stores

The library, `picasso.db`, holds the folders you added, every photo's stars, caption, rotation, place, fixed date, albums, and edits, your presets, and your GPS tracks.
It does not contain the photo or video files. Back up your media files separately.

The cache holds thumbnails, map tiles and duplicate-search hashes.
Clearing it does not remove source files or library edits. Picasso rebuilds thumbnails and downloads map tiles as needed.
Your choices in Settings and your recent searches are kept in `settings.json`, apart from the library.
*Settings → Storage* shows where each one is.

Two sidecar files may be stored beside your photos: `.picasso-geotags.json` contains locations assigned with *Geotag from GPS track…*, and `.picasso-renames.json` records names that *Undo* can restore after *Rename files…*.
Back up these files with your media if you want to preserve them.

=== Default storage locations

*Settings → Storage* shows the actual paths on your computer. The default locations are:

* Windows: library `%APPDATA%\Picasso\picasso\data`; cache `%LOCALAPPDATA%\Picasso\picasso\cache`; settings `%APPDATA%\Picasso\picasso\config\settings.json`.
* macOS: library `~/Library/Application Support/app.Picasso.picasso`; cache `~/Library/Caches/app.Picasso.picasso`; settings `~/Library/Application Support/app.Picasso.picasso/settings.json`.
* Linux: library `~/.local/share/picasso`; cache `~/.cache/picasso`; settings `~/.config/picasso/settings.json`.

You can copy the settings file to preserve preferences. A saved CARTO key is encrypted for the current computer and must be entered again on another computer.

=== Backups

At startup, Picasso creates a backup if none exists or the newest backup is at least one week old.
Backups are stored in a `backups` folder beside the library; the five newest are kept.
A library backup includes edits and their history, but excludes media files, `settings.json` and the cache.
Copy the settings file separately if you want to preserve your preferences.
In *Settings → Storage*, *Back up now* makes one, and *Restore…* puts one back: Picasso backs up the current library first, then restarts with the one you chose.

[#recovery]
=== When the library cannot be opened

If the library cannot be opened, Picasso shows a recovery window instead of the library.
Read the error before choosing an action:

* *Try again*, for when the library was only busy, such as while a backup or sync tool had it open.
* *Restore the backup of …* puts the newest readable backup in its place.
Changes since that backup are lost.
* *Start a new library* starts over with your Pictures folder.
* *Open library folder* shows the files, and *Quit* leaves everything as it is.

Restoring and starting over are offered only when the library file is damaged.
A busy or inaccessible library is not replaced.
The damaged file is preserved beside the new one, renamed `picasso-damaged-` with the date.
Preserving that file does not guarantee that all its data can be recovered.
Restoring a backup returns the library to the state recorded in that backup.

=== Moving and renaming folders

Picasso rescans your folders when it starts and watches them while it runs; kbd:[F5] rescans them now.

* Moving photos between folders Picasso already watches needs nothing; the next scan finds them.
* To move a whole folder somewhere new, move it, remove the old place in *Settings → Folders*, and add the new one with *+ Import*.
Picasso can restore their stars, captions, albums and edits when file size, modification time and capture date still match the earlier records.
* A folder on a drive that isn't plugged in keeps its photos until the drive is back.

When a photo is removed from the library, Picasso retains its stars, caption, albums and edits for 90 days so they can be restored if the file returns.

== Privacy and offline use

Photo browsing, editing, search and library statistics run locally.
Places and the Map panel contact map providers for tiles.
Elevation lookup requests terrain tiles, and update checks contact GitHub.
Map and terrain requests reveal the requested areas to their providers.
To work offline, use local photo features and Travel Map; cached map views may also be available.
Disable automatic update checks in *Settings → General* if you do not want those requests.

== Troubleshooting

Videos are missing or do not play::
Install FFmpeg (see <<ffmpeg>>) and start Picasso again.
Videos found while FFmpeg was missing are added then.

The map is blank::
Maps need an internet connection.
If you picked *CARTO*, check that its key is entered in *Settings → Map*, or switch to *OpenFreeMap Liberty*.

A photo is missing::
Check that its folder is in *Settings → Folders* and not under *Excluded folders*, and that its type is ticked in *Settings → File types*.
Press kbd:[F5] to rescan, and look at the files that couldn't be read in the status bar.

The Mac says Picasso can't be opened::
See <<install>>: use *Open Anyway* in *System Settings → Privacy & Security*.

The AppImage does not start::
Run it with `--appimage-extract-and-run` where FUSE is missing, as in containers.

GPS matching finds no photos or assigns the wrong places::
See <<geotagging>>. Check that the track contains timestamps and covers the photo times.
Verify the camera time zone, then preview the command-line results before saving.

Edits are missing in another application::
Edits are stored in the Picasso library, not in the source photo.
Use <<exporting>> to create a file with the edits applied.

Picasso reports that the library cannot be opened::
See <<recovery>>.
